name: mc-monitor
description: 跨境竞品与海外舆情双模式实时监控技能。Mode A 追踪 BSR 排名、Review 增速、价格变动与新品爆款；Mode B 追踪品牌海外口碑流速（Amazon 差评/Reddit/TikTok/Trustpilot/BBB）、10 项危机升格信号与高敏情绪叠加。用户说"BSR 排名""竞品卖得怎么样""品类爆款""帮我盯一下舆情""海外口碑会不会发酵"时触发。
---

## 触发条件

当用户提到以下任意情形时使用本技能：

**Mode A：竞品与货盘数据监控**
- "BSR 排名" / "Best Seller Rank" / "热销排行"
- "竞品卖得怎么样" / "竞品销量" / "对手卖了多少"
- "品类爆款" / "什么卖得好" / "最近什么火了"
- "Review 增速" / "评价趋势" / "review velocity"
- "价格追踪" / "Keepa" / "价格变动"
- "新品上架" / "new arrivals" / "新品趋势"
- "Top sellers" / "类目排名" / "市场份额"

**Mode B：海外品牌口碑与舆情流速监控**
- "帮我盯一下海外舆情" / "这条 Reddit/TikTok 负面会不会发酵"
- "最近 1 星差评突然多了" / "Trustpilot 被刷负评" / "要不要发声明"
- 由 `mc-diagnose` 的 `pr_crisis` 模式或负面三级分流门禁（Tier 2 暗中盯盘 / Tier 3 危机追踪）路由而来

**与 mc-compete 的区别：**
- mc-compete = 竞品**策略**分析（品牌定位、打法拆解、推广策略、威胁评估）
- mc-monitor = 竞品**数据**监控（BSR 排名、Review 数据、价格走势、新品动态）+ 品牌**海外舆情**监控（谁在说、传多快、情绪多烫）

两者互补，可串联使用：先用 mc-monitor 看数据全貌，再用 mc-compete 深挖策略。

---

## 模式判定

- 涉及竞品销量、BSR、爆款或 Keepa 价格 → **Mode A**（执行下方模块 1–4）。
- 涉及品牌负面、突发差评、Reddit/TikTok/Trustpilot 吐槽发酵或召回舆情 → **Mode B**（执行下方「Mode B：海外品牌口碑与舆情流速监控」）。
- 两者同时出现时**优先跑 Mode B**（危机止血不等人）。

## 输入要求

执行本技能前，必须确认以下参数：

| 参数 | 是否必须 | 说明 |
|------|---------|------|
| 品类 / 品牌与事件 | 必须 | Mode A 填业务品类；Mode B 填品牌名 + 核心事件/ASIN |
| 平台 | 必须 | Amazon / Shopee / TikTok Shop / Temu / Reddit / Trustpilot（默认 Amazon US） |
| 竞品品牌 | 选填 | Mode A 指定竞品，不指定则扫描品类 Top 卖家 |
| 时间窗口 | 选填 | Mode A 默认近 30 天；Mode B 按小时或近 24–72 小时 |
| 目标市场 | 选填 | 默认 US，可指定 UK / DE / JP / 东南亚各站等 |

无需依赖 brief.md 或 campaign 目录。用户直接告诉品类/事件和平台即可执行。

## 数据收集协议

### 工具探测

执行前检查当前环境中可用的搜索或浏览工具（WebSearch、WebFetch、浏览器工具、MCP 搜索服务、agent-reach 等）。有搜索工具时优先搜索获取多条结果；有浏览工具时读取单页详情。不绑定具体工具名称，使用任何能访问外部实时数据的工具。

### 数据清单

Mode A 收集以下 6 类数据，每类执行 1-3 条搜索（Mode B 检索模板见下文 Mode B 章节）。搜索语言跟随目标市场（US 用英文，JP 用日文，通用分析用英文）：

| 数据类型 | 搜索模板示例 |
|---------|------------|
| BSR 热销排行 | `[category] best sellers Amazon [market]`、`[category] top selling [platform]` |
| 竞品 ASIN/SKU 表现 | `[brand] [product] Amazon BSR`、`[brand] reviews rating [platform]` |
| Review 增速 | `[ASIN] review count trend`、`[brand] [product] review velocity` |
| 价格追踪 | `[ASIN] price history Keepa`、`[brand] [product] price [platform]` |
| 新品上架 | `[category] new releases Amazon`、`[category] new arrivals [platform]` |
| 品类市场数据 | `[category] market size [market]`、`[category] Amazon search volume trend` |

### 平台差异

| 平台 | 核心指标 | 数据特点 |
|------|---------|---------|
| Amazon | BSR、Review Count、Rating、Price History | BSR 是核心排名指标，Keepa 追踪价格历史 |
| Shopee | 销量、评价数、关注人数 | 销量直接可见，关注品牌官方店数据 |
| TikTok Shop | 销量、短视频/直播带货数据、评价 | 内容驱动销售，关注带货达人和视频数据 |
| Temu | 销量标签、价格、评价 | 极致低价竞争，关注价格带和 Temu 推荐权重 |

### 降级处理

如当前环境无可用工具，跳过数据收集步骤，继续正常执行。在交付卡中标注：⚠️ 本次未检索实时数据，建议人工核验关键数据点。

### 引用格式

数据融入正文时用方括号数字标注来源序号：

> 该品类 BSR Top 10 中有 3 款为近 30 天新上架[1]

交付卡末尾附来源清单：

📊 数据来源
[1] 来源名称 / URL，检索日期 YYYY-MM-DD
[2] ...

如数据来自推断或无确凿来源，标注为：[推断，基于可比品类/历史趋势]，勿省略标注。

### 数据置信分级

通用 web 搜索通常拿不到真实销量。每个销量/价格类数字必须标注置信级别：

| 级别 | 含义 | 标注 |
|------|------|------|
| 实测 | 来自平台页面直接抓取（商品页 Review 数、标价、BSR 排名） | `[实测·{平台}]` |
| 三方估算 | 来自数据工具或媒体报道（Helium 10 / Jungle Scout / Keepa 等，标注工具/媒体名） | `[估算·{来源名}]` |
| 推断 | 由可比品类、Review 数倍率等间接推算 | `[推断]` |

**硬规则**：`[推断]` 级数字不得作为「定价建议」「我方对标分析」结论的唯一依据——
推断数字只能用于方向性判断（涨/跌/量级），不能用于精确对比。
关键决策数字（市场规模、竞品月销）需 ≥2 个独立来源；来源冲突时输出区间而非单值。

## 模块 1：品类热销看板

扫描品类在目标平台的 BSR 排行，建立市场基准。

```markdown
## 品类热销 Top 10

**品类：** {品类名}
**平台：** {平台名}（{目标市场}）
**时间窗口：** 近 {N} 天

| BSR 排名 | 商品名 | 品牌 | 价格 | Reviews | Rating | 核心卖点 | 趋势 |
|---------|--------|------|------|---------|--------|---------|------|
| #1 | ... | ... | $XX.XX | ~X,XXX | 4.X | ... | ↑/↓/→ |
| #2 | ... | ... | $XX.XX | ~X,XXX | 4.X | ... | ↑/↓/→ |
| ... | | | | | | | |

### 品类洞察
- **主力价格带**：${区间}（占 Top 10 中 {N} 款）
- **主流功能/卖点**：{品类中反复出现的功能关键词和 A+ Content 主题}
- **空白机会**：{Top 10 未覆盖但有搜索需求的方向}
- **市场集中度**：Top 3 品牌占据 BSR Top 10 中 {N} 席，集中度{高/中/低}
```

### 执行要点
- 货币单位跟随目标市场（US → $，UK → £，DE → €，JP → ¥）
- Amazon 以 BSR 为主排名依据，Shopee/TikTok Shop 以销量为主
- 趋势判断依据：BSR 排名上升 ↑、下降 ↓、稳定 →（相较上一周期）
- 市场集中度 = Top 3 品牌在 Top 10 中的席位数（≥7 席为高集中度）

## 模块 2：竞品商品追踪

对指定竞品进行 ASIN/SKU 级深度追踪。

```markdown
## 竞品商品追踪

### {竞品品牌 A}

**品牌概况：** 预估品类市场份额 ~{X}%，主力产品 {N} 款

**核心 ASIN/SKU 矩阵：**

| ASIN/SKU | 商品名 | 价格 | BSR | Reviews | Rating | 上架时间 | 趋势 |
|----------|--------|------|-----|---------|--------|---------|------|
| B0XXXXXXX | ... | $XX.XX | #XX | X,XXX | 4.X | YYYY-MM | ↑/↓/→ |

**价格与 Review 变化（近 {N} 天）：**
- 调价记录：{核心 ASIN 的价格变动，如有}
- Review 增速：{日均新增 Review 数，对比品类平均}
- Rating 变化：{评分趋势，是否下滑}

**新品与变体动态：**
- 新品上架：{近期新增 ASIN/变体}
- 变体扩展：{新增颜色/尺寸/包装规格}
- 下架/缺货：{近期下架或长期缺货的 SKU}

**履约模式分析（Amazon）：**
- FBA vs FBM 分布：{核心 ASIN 的履约方式}
- Prime 标记覆盖率：{X}%
- 库存信号：{是否出现"仅剩 X 件"等低库存提示}
```

### 执行要点
- 每个竞品品牌独立一个子章节
- ASIN 是 Amazon 标识，Shopee 用商品 ID，TikTok Shop 用商品链接
- FBA/FBM 分析仅适用于 Amazon，其他平台跳过此项
- Review 增速 = 近 30 天新增 Review / 30，与品类均值对比

## 模块 3：新品爆款雷达

捕捉品类中 BSR 攀升最快的新品，识别增长信号。

```markdown
## 新品爆款雷达

### BSR 攀升最快新品（近 {N} 天）

| 商品名 | 品牌 | ASIN/SKU | 上架时间 | 当前 BSR | BSR 变化 | 价格 | Reviews |
|--------|------|----------|---------|---------|---------|------|---------|
| ... | ... | B0XXXXXXX | YYYY-MM-DD | #XX | ↑{N}位 | $XX.XX | ~XX |

### 爆款启动策略分析

**定价策略：**
- 初始定价模式：{低价冲量 / 正常定价 / 高价高质}
- 与品类均价对比：{低于/持平/高于均价 {X}%}

**Review 积累策略：**
- Review 增速：上架 {N} 天内获得 {M} 条 Review
- Vine 计划参与：{是/否/疑似}
- Review 质量：{是否有大量带图/视频 Review}

**广告与流量信号：**
- Sponsored 标记频率：{在搜索结果中出现 Sponsored 的频率}
- 关键词覆盖：{出现在哪些高流量关键词的搜索结果中}
- 社媒/站外引流信号：{是否有 TikTok/Instagram/YouTube 相关内容}

### 品类趋势信号
- **上升趋势**：{品类中正在变强的特征/功能/定位}
- **衰退信号**：{BSR 持续下滑的产品共性}
- **季节性因素**：{当前时段是否有季节性波动}
```

### 执行要点
- "新品"定义：上架时间 ≤ 90 天
- BSR 攀升速度 = 当前 BSR vs 首次记录 BSR 的变化幅度
- Vine 计划判断依据：短时间内出现大量 "Vine Voice" 标签的 Review
- 各平台新品入口不同：Amazon → New Releases，Shopee → 新品专区，TikTok Shop → 近期上架排序

## 模块 4：价格与促销动态

追踪品类价格带分布与竞品促销节奏。

```markdown

### 品类价格带分布

| 价格带 | 商品占比 | 代表品牌/ASIN | 平均 Rating | 趋势 |
|--------|---------|--------------|------------|------|
| $0-15 | XX% | ... | 4.X | ↑/↓/→ |
| $15-30 | XX% | ... | 4.X | ↑/↓/→ |
| $30-50 | XX% | ... | 4.X | ↑/↓/→ |
| $50+ | XX% | ... | 4.X | ↑/↓/→ |

### 竞品价格走势（Keepa 风格）

| 品牌 | ASIN/SKU | 当前价 | 30 天最低 | 30 天最高 | 90 天均价 | 趋势 |
|------|----------|-------|----------|----------|----------|------|
| ... | B0XXXXXXX | $XX.XX | $XX.XX | $XX.XX | $XX.XX | ↑/↓/→ |

### Deal / Coupon / 促销日历

| 竞品 | 促销类型 | 时间 | 折扣力度 | 预估 BSR 影响 |
|------|---------|------|---------|-------------|
| ... | Lightning Deal | MM-DD | -XX% | BSR 升 ~{N} 位 |
| ... | Coupon（页面 Coupon） | 持续中 | -$X / -X% | — |
| ... | Subscribe & Save | 持续 | -X% | 稳定复购 |

### 定价建议
- **品类甜蜜价格带**：${区间}（该价格带 Review/Rating 最优，需求集中）
- **竞品定价策略识别**：{渗透定价 / 撇脂定价 / 跟随定价}
- **调价建议**：{基于当前竞争格局，建议我方产品定在 ${区间}，理由}
- **促销时机**：{建议参与的促销类型和时间窗口，结合平台大促日历}
```

### 执行要点
- 价格带划分根据品类实际分布调整，上表为示例
- Keepa 数据仅适用于 Amazon，其他平台用可获取的历史价格数据
- 促销类型按平台区分：
  - Amazon：Lightning Deal、Best Deal、Coupon、Subscribe & Save、Prime Exclusive
  - Shopee：Flash Sale、Voucher、Free Shipping
  - TikTok Shop：限时折扣、达人专属价
  - Temu：平台降价、拼单价
- 平台大促日历（关键节点）：Prime Day（7月）、Black Friday（11月）、Shopee 9.9/11.11/12.12、TikTok Shop 大促

## Mode B：海外品牌口碑与舆情流速监控

承接 `mc-diagnose` 的 `pr_crisis` 路由，回答"这条海外负面在哪个阵地、扩散多快、触发了哪几层情绪"。本模式只负责监测与研判，不直接起草对外公关声明（声明由 `mc-diagnose` / `mc-brand` 定策略、`mc-compliance` 过 7 项否决）。

### B1：跨境舆情检索清单

| 监控维度 | 搜索与核查示例（跟随目标市场语言） |
|---------|---------------------------------|
| 首发与讨论阵地 | `site:reddit.com "{brand}" {issue}`、`"{brand}" scam OR broken OR recall` |
| 店铺与评价平台 | Amazon ASIN 近 7/30 天 1–3★ 差评增速、NCX 退货原因、Trustpilot / BBB 近 7 天评分变动 |
| 社媒与视频拆解 | TikTok / YouTube / X 关键词 `"{brand}" review warning OR boycott`、浏览/点赞/转发小时增速 |
| 监管与召回公开库 | CPSC.gov / FDA Recalls / EU Safety Gate (RAPEX) 是否出现品类或供应链关联通报 |

### B2：10 项危机升格信号追踪（与 `mc-diagnose` 对齐）

逐项核对，任一命中即提示 `mc-diagnose` 升级至 Tier 3 响应：
1. 监管/消保机构点名（CPSC / FDA / RAPEX / ACCC）
2. 头部 YouTuber / TikToker 拆解曝光
3. Reddit / X / TikTok 互动流速小时级激增且不衰减
4. 评论区一边倒谴责
5. Amazon 近 7 天出现多条相同缺陷 1★ 差评
6. 涉及人身安全、过敏、儿童或宠物健康
7. Amazon NCX / "Frequently Returned" 标或安全下架预警
8. 买家 PII / 后台敏感数据 / 内部邮件外泄
9. Trustpilot / BBB 断崖或 Google 品牌词首屏被避雷贴占据
10. 包含 `≥ 2` 类高敏情绪叠加（见 B3）

### B3：海外 5 类公众高敏情绪叠加雷达

单一不满多半可控，两类以上情绪共振时燃点会急剧下降：

| 高敏情绪类别 | 跨境典型触发点 | 是否命中 |
|------------|-------------|---------|
| **① 价格/品质双标与隐瞒背刺** | 同款国内外差价或偷偷减配、隐性订阅扣费不让取消 | 是 / 否 |
| **② 傲慢推诿 / "User Error" 说教** | 官方回复归咎买家不会用、"We apologize if you felt..." 非道歉 | 是 / 否 |
| **③ 人身 / 食品接触 / 儿童 / 宠物安全** | 过热起火、过敏、BPA/重金属超标、宠物误食或生病 | 是 / 否 |
| **④ 文化 / 宗教 / 族裔 / 性别冒犯** | 素材触碰种族刻板印象、文化挪用、清真/宗教禁忌 | 是 / 否 |
| **⑤ 环保漂绿（Greenwashing）与劳工伦理** | 吹嘘 "100% Eco-Friendly" 被扒出塑料包装或代工血汗指控 | 是 / 否 |

### B4：跨平台外溢与输出看板

追踪跨平台跃迁路径（`Amazon 1★ 投诉 → Reddit r/AmazonPrime 或垂直板块长帖 → TikTok 避雷短视频切片 → YouTube 汇总 → Google 品牌词 SERP 首屏长期占位`）：

```markdown
## 海外舆情流速与情绪燃点看板

**品牌 / ASIN：** {品牌名}　**监测窗口：** {当前年份}-{MM}-{DD} {HH}:{mm} 起近 {N} 小时
**分流结论：** Tier {1/2/3}（命中升格信号：{编号或"无"}）

| 时段 | 阵地互动量 / 差评增量 | 跨平台新增讨论数 | 走势 | 数据置信 |
|------|-------------------|----------------|------|---------|
| {时段} | {数值} | {数值} | ↑/↓/→ | `[实测·{平台}]` / `[估算·{来源}]` / `[推断]` |

- **高敏情绪叠加**：{类别列表}（共 {N} 类）
- **评论倾向抽样**：谴责 {X}% / 中立 {Y}% / 支持 {Z}%（样本 {n} 条，置信标注）
- **走势研判与建议交接**：{升温/平台期/衰减} → {Tier 2 盯盘 / 交 mc-diagnose 定象限 / 交 mc-compliance 审声明}
- **下次复查时间**：{具体时间点}
```

**Mode B 纪律**：严禁把 `[推断]` 数字当作"已全网破圈"的唯一依据；仅做公开信息检索，不得搜集或传播素人个人隐私信息（遵守 GDPR/CCPA）。

## 输出格式

Mode B 完整报告即上方「海外舆情流速与情绪燃点看板」。Mode A 完整报告包含 4 个模块。用户可以只要求其中某个模块：
- "BSR 排行" / "品类 Top 10" → 模块 1
- "竞品商品" / "XX 的 ASIN 表现" → 模块 2
- "新品趋势" / "最近什么爆了" → 模块 3
- "价格动态" / "促销日历" → 模块 4

## 交互规则

- 用户可以随时追问细节："展开 XX 品牌的 ASIN 分析"
- 用户可以调整时间窗口："看看近 7 天 / 近 90 天的数据"
- 用户可以追加监控对象："再加上 XX 品牌"
- 用户可以切换平台："同一品类在 Shopee 上呢？"
- 与 mc-compete 联动：monitor 数据可以喂给 mc-compete 做策略分析
- 与 mc-listing 联动：发现竞品 Listing 优势后可以用 mc-listing 优化自己的 Listing

## 交付规范

执行完成后**必须**以下格式收尾：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ mc-monitor · 竞品监控完成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📌 执行摘要
   · 品类：{品类名} · 平台：{平台名}
   · BSR Top 1：{商品名}（{品牌}，Reviews ~{N}）
   · 竞品追踪：{N} 个品牌，{M} 个核心 ASIN
   · 近期爆款：{N} 个新品进入 BSR Top 100
   · 关键信号：{一句话最值得关注的市场变化}

📊 数据来源
   [1] ...

➡️  下一步：
   · 用 mc-compete 对关键竞品做策略分析
   · 用 mc-listing 优化自己的 Listing 竞争力
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

如需展开查看任意模块，用户说"展开 XX 部分"即可。

> **Mode B 交付卡调整**：执行摘要替换为 `· 分流：Tier {1/2/3} · 升格信号：{命中编号或"无"} · 高敏情绪：{N} 类 · 走势：{升温/平台期/衰减}`；下一步替换为交接 `mc-diagnose`（象限定位与止血闸门）或 `mc-compliance`（声明 7 项否决检视）。
